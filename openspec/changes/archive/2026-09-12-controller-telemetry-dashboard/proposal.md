# Proposal: Телеметрическая панель в консольном пульте

## Why

Сейчас `controller.py` показывает только проценты (lin/ang) и **выбрасывает** ack-телеметрию бота (читает в «мусор», чтобы не забить буфер). Пользователь не видит фактических значений команды (мм/с, рад/с) и того, что реально происходит с моторами (измеренная скорость, ШИМ, интеграл) — невозможно наблюдать и отлаживать качество управления вживую.

## What Changes

- Статусная строка показывает значения команды в абсолютных единицах вместе с процентами: `lin +30% (90.0 мм/с) · ang -10% (-0.32 рад/с)`.
- Пульта переходит в полноэкранный режим (alt-screen buffer, скрытие каретки): статус сверху, под ним живая таблица последних **20** ack (свежие **сверху**), футер-подсказки снизу.
- ack-строки разбираются (n, v, w, mL, mR, oL, oR, iL, iR) и складываются в кольцевой буфер `deque(20)`; при перерисовке экрана на каждый новый ack показываются только актуальные строки.
- Последняя (самая свежая) строка таблицы подсвечивается инверсией.
- Кольцевой буфер очищается после переподключения (значения мёртвой линии не смешиваются со свежими).
- Все внутренние сообщения пульт (подключение, «Связь потеряна», подсказки) рисуются **внутри** панели, а не поверх экрана.
- На выходе (`q`, Ctrl+C, исчерпание реконнекта) экран восстанавливается (выход из alt-screen, видимая каретка).
- Поведение управления (стрелки, heartbeat, автореконнект, stop) не меняется.

## Capabilities

- **New Capabilities**: нет.
- **Modified Capabilities**: `pc-keyboard-control` — меняется требование к UI консольного приложения: показ абсолютных значений команды и живая панель телеметрии (вместо «только проценты» и «ack молча в мусор»).

## Implementation Considerations

- Прошивка не меняется: ack-формат уже содержит всё нужное (`mL/mR/oL/oR/iL/iR`).
- Рендерер — чистые функции (parse + форматирование строк), пригодные для PTY-тестов, чтобы не сломать существующие 15/15.

## Impact

- `src/motor_controller/motor_controller/controller.py` — добавление парсера ack, кольцевого буфера и рендерера панели; терминальные escape-переходы.
- Существующие PTY-тесты controller.py остаются критерием регрессии.
- Никаких изменений прошивки, протокола и физики канала.
