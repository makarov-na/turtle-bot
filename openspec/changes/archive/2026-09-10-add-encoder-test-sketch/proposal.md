## Why

У нас появилась возможность работать с контроллером через HC-06, но есть проблемы с управлением ботом. Нужно проверить, что энкодеры корректно читаются после переноса на PORTC (A0-A3) — особенно направления вращения. Для этого нужен отдельный тестовый скетч: человек крутит колёса руками и видит значения энкодеров (включая направление) и скорость.

**Важно:** при реализации обнаружено, что библиотека `SoftwareSerial` на ATmega328P алиасит `PCINT1_vect` (и `PCINT2_vect`) на `PCINT0_vect`. Поэтому SoftwareSerial нельзя совместить с `ISR(PCINT1_vect)` для энкодеров — текущий `motor_controller.ino` из-за этого не компилируется. Тестовый скетч использует Hardware Serial (USB) вместо HC-06.

## What Changes

- Новый отдельный скетч `encoder_test.ino` в `src/motor_controller/encoder_test/` (отдельная папка — Arduino компилирует .ino в одной папке в единую программу, соседство с `motor_controller.ino` невозможно)
- Скетч читает энкодеры через ISR (PORTC, A0-A3) — как в `motor_controller.ino`
- Выводит значения тиков каждого колеса со знаком (плюс = бот едет вперёд) и скорость в мм/с
- Вывод через Hardware Serial (D0/D1), HC-06 подключён на D0/D1, раз в секунду, построчно
- Драйвер моторов в скетче не задействуется — только чтение энкодеров
- `motor_controller.ino` не изменяется

## Capabilities

### New Capabilities
- `encoder-test-sketch`: отдельный тестовый скетч для проверки чтения энкодеров и направлений (вывод через USB/Hardware Serial)

### Modified Capabilities
- (нет)

## Impact

- **Firmware**: новый файл `src/motor_controller/encoder_test/encoder_test.ino`
- **Направления**: связь знака тиков с направлением движения бота (правый мотор по часовой, левый против; `motorSign` применён к выводу)
- **Проверка**: `motor_controller.ino` остаётся нетронутым
- **Открытый вопрос по боевому скетчу**: `motor_controller.ino` с SoftwareSerial + ISR PCINT1 не компилируется (конфликт `__vector_4`); это требует отдельного решения
